## 二、手册里说错的地方（更正）

### ❌ 更正 1：角色文件不是"完整 character_config"，就是**只写差异**

**手册里我写错了。** 我当时读到官方文档说"格式与 conf.yaml 基本一致……将 character_config 的内容贴进去"，就推断必须写完整块。**实际不是。**

真正生效的代码在 `src/open_llm_vtuber/service_context.py:504`：

```python
# Start with original config data and perform a deep merge
new_character_config_data = deep_merge(
    self.config.character_config.model_dump(), alt_config_data
)
```

`deep_merge` 把角色文件**深合并**进基础配置，角色文件的值优先。所以：

- ✅ **只写你要改的项就够了**，没写的自动沿用 `conf.yaml`
- ✅ 这也解释了为什么项目自带的 `characters/zh_米粒.yaml` 只有 13 行还能正常工作
- ⚠️ 但要注意：**单独拿角色文件去做校验会失败**（`CharacterConfig` 要求 agent_config 等字段必填）。这是因为校验发生在**合并之后**，不是在读文件时。所以"校验报缺字段"不等于你的文件错了。

结论：我给你的 `xiaoxing.yaml` 写法是**对的**，手册里那段"改用全量版"的建议**不需要执行**。

### ❌ 更正 2：`piper_tts` 在 v1.2.1 里**根本不存在**

`config_templates` 的注释里列了 `'piper_tts'`，但 `src/open_llm_vtuber/tts/` 目录下**没有 `piper_tts.py`**，`tts_factory.py` 里也没有对应分支。照手册去配 piper 会直接报 `Unknown TTS engine type`。

v1.2.1 实际存在的 TTS 引擎（来自 `tts_factory.py`）：

```
bark_tts, edge_tts, pyttsx3_tts, cosyvoice_tts, cosyvoice2_tts,
melo_tts, x_tts, gpt_sovits_tts, siliconflow_tts, coqui_tts,
fish_api_tts, minimax_tts, sherpa_onnx_tts, openai_tts, spark_tts
```

**所以离线方案要用 `sherpa_onnx_tts`**（已配好）。

## 三、只有实跑才会暴露的 3 个坑

### 坑 1：edge-tts 在这台机器上被 **403 封锁**，角色会完全没声音

默认 `tts_model: 'edge_tts'`，实跑报：

```
CRITICAL | edge_tts | Error: edge-tts unable to generate audio: 403
CRITICAL | edge_tts | It's possible that edge-tts is blocked in your region.
```

**关键点：不带代理也一样失败**（实测过）。这是微软侧对本地网络出口的封锁，不是配置问题，也不是代理问题。任何照默认配置装的人都会遇到"AI 会打字但完全不出声"。

**已解决**：改用本地离线 TTS `sherpa_onnx_tts`，模型用 `vits-melo-tts-zh_en`（中英双语，159 MB），放在 `models/vits-melo-tts-zh_en/`。

⚠️ **一个模板里的坑**：配置模板里 `sid: 1`，但这个模型**只有 1 个说话人**，必须填 `sid: 0`，否则每次都告警 `This model contains only 1 speakers. sid should be in the range [0, 0]`。

### 坑 2：推理模型会把 token 预算全烧在"思考"上，正文为空 → 角色不出声

这是**最隐蔽**的一个。实测同一个模型、同一个问题：

| `max_tokens` | 思考 token | 正文 |
|---|---|---|
| 60 | 60 | **空** |
| 400 | 109 | 105 字 ✅ |
| 1500 | 93 | 149 字 ✅ |

`qwen3.8-27b-uncensored` 是**推理模型**。Open-LLM-VTuber 原来的代码**不发送 `max_tokens`**（源码注释写着 `# up to the user to set the max_tokens`），于是用 LM Studio 的默认值 —— 而默认值太小，思考内容就把预算吃光了，正文是空字符串。

空字符串 → TTS 没有文本可合成 → **前端一片安静**。日志里只看到一句无害的 `Ignore OOV ':'`，极具误导性。

**已解决**：给项目打了个小补丁，新增 `max_tokens` 配置项（默认不发送，完全向后兼容）：
- `src/open_llm_vtuber/config_manager/stateless_llm.py` —— 新增 `max_tokens` 字段
- `src/open_llm_vtuber/agent/stateless_llm_factory.py` —— 传递该参数
- `src/open_llm_vtuber/agent/stateless_llm/openai_compatible_llm.py` —— 仅在配置了才发送
- `conf.yaml` —— `lmstudio_llm.max_tokens: 1024`

> 升级项目后这个补丁可能被覆盖，届时重新加一遍，或在 LM Studio 里换一个**非推理模型**。

### 坑 3：LM Studio 的上下文长度设成 262144，会把流式响应拖到 30 秒以上

模型自己的默认加载配置里写的是 `contextLength: 262144`（25.6 万！），还有 4 个并行槽位。后果是**流式输出极慢**：

| 配置 | 首字延迟 | 整句耗时 |
|---|---|---|
| context 262144 / 4 并行 | **31.7 秒** | 33.7 秒 |
| context 16384 / 1 并行 | **5.0 秒** | 6.6 秒 |

**已解决**：把模型默认加载配置改成 `contextLength: 16384` + `numParallelSessions: 1`
（文件：`~/.lmstudio/.internal/user-concrete-model-default-config/JonathanColetti/Qwen3.8-27B-Uncensored-GGUF/Qwen3.8-27B-Uncensored-noMTP-Q4_K_M.gguf.json`，原文件已备份为 `.bak`）

**提速 6 倍**。对陪伴型对话来说 16384 上下文完全够用。

## 四、过程中的一个插曲（附排查方法）

调试期间 **LM Studio 服务崩溃退出过一次**，Open-LLM-VTuber 报 `Error code: 502`，一度让我误以为是 `max_tokens` 改动导致的。

崩溃前的日志特征（`%APPDATA%\LM Studio\logs\main.log`）：

```
[error] ... Error: Local inference is changing ownership. Please try again shortly.
```

排查结论：**502 是后端崩溃，与配置改动无关**（重启 LM Studio 后 `max_tokens` 完全正常）。

**恢复方法**：如果以后又遇到 502 或"连不上 1234"：

```powershell
# 1) 看服务是否还活着
& "$env:USERPROFILE\.lmstudio\bin\lms.exe" ps
# 2) 若报 "Timed out waiting for LM Studio daemon to start"，说明主程序挂了，重新打开 LM Studio 即可
#    用桌面会话启动最稳：
Start-Process explorer.exe -ArgumentList '"C:\Program Files\LM Studio\LM Studio.exe"'
```

## 六、还需要你确认的两件事

### 1. 模型：你有两个选择

这台机器上实际只有 **`qwen3.8-27b-uncensored`**（27B，Q4_K_M，17.5 GB）。你原本以为装好的 `Qwen3.6-35B-A3B` **并不在这台机器上**。

当前配置用的就是 `qwen3.8-27b-uncensored`，**已经跑通**。它的缺点是：
- 是**推理模型**，每次回复前有 5 秒左右的思考延迟
- 未经审查的微调版，回答风格比较放飞（从"我是Mili，一个迟早要统治世界的AI VTuber"这类默认人设回复能看出来）

如果你想要**更快、更适合实时语音**的模型，建议换 **Qwen3.6-35B-A3B**（MoE，激活参数仅 3.5B，速度快很多），在 LM Studio 里搜索下载 Q4_K_M（约 21 GB）即可。下载后只需把 `conf.yaml` 里 `lmstudio_llm.model` 改成新模型在 `/v1/models` 里的 id。

### 2. MCP 点击工具（可选，尚未安装）

`windows-mcp`（屏幕点击/OCR）和 `filesystem`（文件搜索）**我没有装**，原因：

- `windows-mcp` 会把**鼠标键盘控制权**交给一个"生气就捣乱"设定的角色，它能读剪贴板、能杀进程
- 建议先稳定用几天，确认人设可控，再决定要不要开

想装的话，按手册第 5 步走，然后把 `mcp_servers.json` 里的对应项取消注释、并在角色 YAML 的 `mcp_enabled_servers` 里加上名字。
