# Open-LLM-VTuber 完整手动配置手册

> 适用版本：**Open-LLM-VTuber v1.2.1**（本文所有字段名都照 v1.2.1 的 `conf.default.yaml` 核对过）
> 目标机器：AMD AI Max+ 395 / 128GB 统一内存 / Windows 11
> 原则：能不写代码就不写代码。全文除"复制粘贴配置"外，只有 3 条一次性安装命令。

---

## 0. 先看这一节：你手上那份配置说明里，有 7 处会直接把你带进坑里

我按官方文档和真实配置文件核对了一遍。你收到的说明里有几个错误，**照做会卡住**，先纠正：

| # | 原说明的说法 | 实际情况 | 后果 |
|---|---|---|---|
| 1 | LM Studio 里已下载 **Qwen3.6-35B-A3B** | 你这台机器上实际只有 `qwen3.8-27b-uncensored`（17.48 GB，qwen35 架构）。LM Studio 服务正在运行，`/v1/models` 返回的 id 是 `qwen3.8-27b-uncensored` | `model:` 填错名字 → 聊天接口直接报 Model not found |
| 2 | 模型文件夹叫 `live2d-models`，但另处又写 `live2d_models` | 官方文档和仓库都是 **`live2d-models`（连字符）** | 模型加载不出来，前端黑屏 |
| 3 | 角色 YAML 里用 `llm_provider: 'openai_compatible_llm'` | 建议改用项目内置的 **`lmstudio_llm`**（专为 LM Studio 预留，base_url 已填好） | 不算错，但多写了配置，且之后换后端容易忘 |
| 4 | 文件搜索用 **mcp-assist** | 该项目**不发布预编译二进制**，官方只给 `go build` 命令 —— 对"不写代码"来说等于没有 | 你会卡在"下载不到 exe" |
| 5 | 情绪要靠 `persona_prompt` 里**自己列**情绪清单 | 系统会自动把 `emotionMap` 里的关键词注入提示词（`live2d_expression_prompt`），**自己列反而会和模型实际表情对不上** | 表情乱跳或不变 |
| 6 | 需要"确保 `mcp_prompt` 已启用" | 同时还要启用 **`live2d_expression_prompt`**，它才是表情系统的开关，模板里默认开着 | 若被注释掉则完全没有表情 |
| 7 | `pip install win32-mcp-server` 装到系统里 | 应该装进**项目自己的虚拟环境**（`.venv`），并且要用 venv 里的绝对路径调用 | 启动 MCP 时报"找不到命令" |

另外补一句：`Qwen3.6-35B-A3B` 这个模型**是真实存在的**（[Qwen 官方博客](https://qwen.ai/blog?id=qwen3.6-35b-a3b)、[lmstudio-community 的 GGUF](https://huggingface.co/lmstudio-community/Qwen3.6-35B-A3B-GGUF)、[liodon-ai 的 imatrix 量化](https://huggingface.co/liodon-ai/Qwen3.6-35B-A3B-imatrix-GGUF) 都在），只是**你这台机器上没下载**。所以你有两个选择：

- **A（推荐，今天就能跑通）**：直接用已有的 `qwen3.8-27b-uncensored`，配置里 `model:` 写它。
- **B**：去 LM Studio 搜 `Qwen3.6-35B-A3B` 下载 Q4_K_M（约 21 GB），下完后把它在 LM Studio 里的 id 原样填进配置。

两种选法的配置位置完全一样，只是 `model:` 那一行的值不同。

## 1. 目标目录结构

先规划好位置。**路径里不要有中文和空格**（官方明确警告过，中文路径会出错）。

```
C:\work\
├── Open-LLM-VTuber\              ← 项目文件夹，必须正好叫这个名字
│   ├── conf.yaml                 ← 主配置（第 2 步，从 config_templates 复制而来）
│   ├── mcp_servers.json          ← MCP 工具注册（第 5 步）
│   ├── model_dict.json           ← Live2D 模型注册表（第 3 步）
│   ├── characters\
│   │   └── xiaoxing.yaml         ← 你的角色（第 4 步，人设写这里）
│   ├── live2d-models\            ← Live2D 模型放这里（第 3 步）
│   │   └── mao_pro\              ← 项目自带，先拿它跑通
│   ├── avatars\                  ← 头像图
│   ├── config_templates\
│   │   └── conf.default.yaml     ← 模板，用来复制成 conf.yaml
│   └── .venv\                    ← 首次启动后自动生成
├── lizhen\                       ← LiZhen 启动器
│   ├── lizhen.exe
│   └── updater.exe
└── olv-config\                   ← 本手册给你的模板文件（我放在这了）
    ├── xiaoxing.yaml
    ├── mcp_servers.json
    └── model_dict_entry.jsonc
```

> LiZhen 的 `lizhen.exe` 要和 `Open-LLM-VTuber` **文件夹同级**。启动器支持两种摆法（同级 / 包含在内），同级最省事。

### 第 0 步：装三个前置工具（一次性，约 10 分钟）

缺任何一个都会启动失败。**FFmpeg 是硬依赖**，没有它会直接报找不到音频文件。

打开 **PowerShell**（Win + X → 终端），逐条粘贴执行：

```powershell
winget install Git.Git
winget install Gyan.FFmpeg
winget install --id=astral-sh.uv -e
```

装完**关掉 PowerShell 再重新开一个**（winget 装完必须重开，否则 PATH 不生效），然后验证：

```powershell
git --version
ffmpeg -version
uv --version
```

三个都能打印出版本号才算过。

> **Python 说明**：你机器上目前只有一个 Windows 商店版的 `python.exe`（是个占位存根，`python --version` 无输出）。这个**不能用**。项目要求 Python **>= 3.10 且 < 3.13**，而商店版默认装最新的 3.13+。所以请去 [python.org](https://www.python.org/downloads/) 下载 **3.12.x** 的 Windows 安装包，安装时**务必勾选 "Add python.exe to PATH"**。
>
> 装完验证：`python --version` 应显示 `Python 3.12.x`。
>
> 只有 `win32-mcp-server`（第三步的可选工具）需要它。想跳过 MCP 点击功能的话，这一步可以先不做。

还有一个建议：安装 **Chrome**。官方明确只推荐 Chrome，Edge 和 Safari 都有已知问题。

### 第 1 步：拿到项目 + 启动器

#### 1.1 下载项目

1. 打开 [Open-LLM-VTuber Releases](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber/releases)，下载最新版里长得像 **`Open-LLM-VTuber-v1.2.1.zip`** 的文件。
   - ⚠️ **不要**用项目主页那个绿色的 "Code → Download ZIP"。官方专门警告过这个。要用 Releases 里的包（里面带了打包好的前端）。
2. 解压到 `C:\work\`。
3. **如果解压出来的文件夹叫 `Open-LLM-VTuber-v1.2.1`，把它重命名成 `Open-LLM-VTuber`**（LiZhen 靠这个名字找项目，必须是这个名）。

> 网络提示：GitHub 在国内可能连不上。开代理，或让代理绕过 `localhost`（否则之后连 LM Studio 会失败）。

#### 1.2 下载 LiZhen 启动器

1. 打开 [Stewitch/LiZhen Releases](https://github.com/Stewitch/LiZhen/releases)，下载最新的 `.zip`。
2. 解压，把里面的 `lizhen.exe`、`updater.exe`、`launcher\` 等**放到 `C:\work\lizhen\`**，也就是和 `Open-LLM-VTuber` 同级。

> LiZhen 是什么：一个用 Python/PySide6 写的图形化启动器，**自动帮你管理 uv 虚拟环境**（每次启动自动检查依赖）、图形化改配置、看日志。它解决了"不写代码"最痛的一环。要求 Windows 10/11 22H2+。

#### 1.3 第一次启动

1. 双击 `C:\work\lizhen\lizhen.exe`。
2. 它会问你要不要创建桌面快捷方式 —— 建议**是**（后面 PowerToys 要用到这个快捷方式或 exe 路径）。
3. 首次启动会自动创建 `.venv` 虚拟环境并安装依赖，**这一步要几分钟到十几分钟**（取决于网速），耐心等，不要关窗口。
4. 如果它提示缺 `conf.yaml`，先按下文第 2 步建好文件再启动。

> **关于 `conf.yaml`（重要）**：从 v1.1.0 起，项目不会自动生成这个文件。你需要手动复制：
> 把 `C:\work\Open-LLM-VTuber\config_templates\conf.default.yaml` 复制到 `C:\work\Open-LLM-VTuber\conf.yaml`（或者用中文版模板 `conf.ZH.default.yaml`，注释是中文的，更适合你）。
>
> 我第一次编辑 `conf.yaml` 就用这份**全新的副本**，不要自己新建空白文件。

### 第 2 步：配置 LLM（连上 LM Studio）

我已经确认过：**你机器上的 LM Studio 服务正在运行**，`http://127.0.0.1:1234/v1/models` 能正常返回，当前可用模型 id 是：

```
qwen3.8-27b-uncensored
```

（还有一个 `text-embedding-nomic-embed-text-v1.5`，那是嵌入模型，不用于聊天。）

#### 2.1 确认 LM Studio 侧设置

打开 LM Studio，`Ctrl + ,` 进设置：

1. **Developer 选项卡** → 打开 **"Just-In-Time model loading"**（按需自动加载，不用手动预载）。
2. 勾选 **"Run LLM server on login"**（开机自启；关窗后它会留在托盘，服务继续跑）。
3. 确认服务端口是 **1234**。

顺手做两件**很影响体验**的事：

- **关掉思考模式（thinking）**。Qwen 系列会输出思考内容，这些内容会被 TTS 念出来、还会拖慢首字响应。在 LM Studio 加载模型时把 thinking / reasoning 相关开关设为关闭（不同版本叫法略有差异，可能在模型加载设置里的 "Reasoning" 或提示词模板选项中）。
- **上下文长度别拉满**。先用 **8192～16384**。设成 32k/64k 会让 KV cache 暴涨、拖慢速度，对话式陪伴用不了那么长。

#### 2.2 把模型 id 抄准（最容易翻车的一步）

`model:` 的值**必须和 LM Studio 暴露的 id 一模一样**。最可靠的取法，在 PowerShell 里跑：

```powershell
(Invoke-WebRequest -Uri 'http://127.0.0.1:1234/v1/models' -UseBasicParsing).Content
```

把 `"id"` 后面的字符串**原样复制**（注意别抄成全角冒号、别带空格）。也可以直接在 LM Studio 界面里点模型名旁边的复制按钮。或者用命令行工具：

```powershell
& "$env:USERPROFILE\.lmstudio\bin\lms.exe" ls
```

（你的 `lms.exe` 确实在 `C:\Users\36322\.lmstudio\bin\`，GamePause 也依赖它，已经在 PATH 的期望位置。）

#### 2.3 改 `conf.yaml`

用记事本或 VS Code 打开 `C:\work\Open-LLM-VTuber\conf.yaml`，找到 `character_config` → `agent_config` → `agent_settings` → `basic_memory_agent`，改这两处：

```yaml
  agent_config:
    conversation_agent_choice: 'basic_memory_agent'

    agent_settings:
      basic_memory_agent:
        llm_provider: 'lmstudio_llm'      # ← 改成这个（项目内置的 LM Studio 预设）
        faster_first_response: True
        segment_method: 'regex'           # ← 中文对话比 pysbd 更稳，也更快
```

然后往下找到 `llm_configs:` → `lmstudio_llm:`，确认：

```yaml
      lmstudio_llm:
        base_url: 'http://localhost:1234/v1'
        model: 'qwen3.8-27b-uncensored'   # ← 换成你 2.2 抄到的 id
        temperature: 0.8                  # 0~2，越高越随机；陪伴角色 0.7~0.9 比较合适
```

> 为什么用 `lmstudio_llm` 而不是 `openai_compatible_llm`？官方源码里，除了 llama.cpp 和 Claude，**其它所有后端本质上都是 `openai_compatible_llm` 的"换皮"**（只是 base_url 和参数预先填好了）。用内置预设代码完全相同，但省事、不易写错。

#### 2.4 `asr_config` 和 `tts_config` 不用动

默认组合是 **sherpa-onnx-asr (SenseVoiceSmall) + edge_tts**，可以直接用：

- **ASR**：首次启动会自动下载 SenseVoice 模型（约 200～300 MB），完全本地运行，中英日韩粤都行。
- **TTS**：`edge_tts` 走微软在线接口，**免费、免配置**，音色很自然。缺点是必须联网。

如果你想让**说话也完全本地、离线可用**，把 `tts_config` 的 `tts_model` 改成 `piper_tts`，然后下载中文模型放到 `models/piper/`：

```yaml
  tts_config:
    tts_model: 'piper_tts'
    piper_tts:
      model_path: 'models/piper/zh_CN-huayan-medium.onnx'
```

Piper 中文模型下载：<https://huggingface.co/rhasspy/piper-voices/tree/main/zh/zh_CN/huayan/medium>
（需要 `.onnx` 和 `.onnx.json` 两个文件一起放进 `models\piper\`。）

想换 edge_tts 的嗓音，先从语音列表里挑：

```powershell
# 需要先装 edge-tts；也可以直接在网上搜 "edge-tts voice list"
# 常用中文音色：
#   zh-CN-XiaoxiaoNeural  温柔女声（默认）
#   zh-CN-XiaoyiNeural    少女音，适合撒娇系角色
#   zh-CN-YunxiNeural     年轻男声
#   zh-CN-YunjianNeural   沉稳男声
```

改 `tts_config` → `edge_tts` → `voice:` 即可。

### 第 3 步：挂载 Live2D 模型

#### 3.1 先用项目自带模型跑通（强烈建议）

**先不要急着找模型。** 项目默认角色配置里用的模型名是 **`mao_pro`**，这个模型**自带在项目里**（真实路径是 `live2d-models\mao_pro\runtime\mao_pro.model3.json`，已经注册在 `model_dict.json` 里了，不用你配）。先让它跑起来，确认"语音 → LLM → 表情 → 口型"整条链路是通的，再换模型。这样出问题时你能确定是环境问题而不是模型问题。

启动后浏览器打开 <http://localhost:12393>，看到角色、能对话，就算通了。

> 自带模型的授权说明在项目根目录的 `LICENSE-Live2D.md` 里。个人自用没问题；**要直播或商用前请先读它**。

#### 3.2 想换模型时的完整流程（4 步）

**第 1 步：下载模型**

⚠️ **版本限制（最关键的一条）**：项目用的渲染库是 `pixi-live2d-display-lipsyncpatch`，**只支持 Cubism 3 / 4 / 5，不支持 Cubism 2**。下载前一定要确认版本。很多老模型（尤其是从老游戏里提取的）是 Cubism 2，**下了也用不了**。

> 补充一个容易踩的坑：项目自带的 `shizuku` 就是**从 Cubism 2.1 转换过来的**，而且它**没有任何表情文件**（连 `expressions` 文件夹都没有）。虽然它的文件还在 `live2d-models\shizuku\` 里，但**官方已经在 2025 年 5 月把它从 `model_dict.json` 里删掉了、列入废弃名单**。官方文档里到处出现的 `shizuku` 例子只是历史遗留的 JSON 示例，**别照它配**。

##### 先看这张表：不是所有官方免费模型都有"表情"

这是选模型时最容易忽略、又最致命的一点 —— **没有 `exp3.json` 表情文件的模型，情绪系统完全不起作用**，你人设写得再好也只会一个表情：

| 模型 | 表情数 | 待机动作组 | 点击区域 Id | 结论 |
|---|---|---|---|---|
| **Niziiro Mao**（=`mao_pro`） | **8 个**（`exp_01`~`exp_08`） | `Idle` | `HitAreaHead` / `HitAreaBody` | ✅ **首选**，项目默认，开箱即用 |
| **Mao**（CubismWebSamples 版） | **8 个** | `Idle` | `HitAreaHead` / `HitAreaBody` | ✅ 可用，和 mao_pro 基本同一个角色 |
| **Haru** | **8 个**（`F01`~`F08`） | `haru_g_idle` | ⚠️ `HitArea` / `HitArea2` | ✅ 有表情，但**点击区域名不一样**，且动作带 `.wav` 音效 |
| **Ren Foster** | **5 个** | `mtn_01` 所在的 Idle 组 | `HitAreaHead` / `HitAreaBody` | ⚠️ Cubism **5.3** 制作，自带渲染核心可能不认，需实测 |
| **Hiyori Momose** | **0 个** | `Hiyori_m01`… | `HitArea` | ❌ 无表情；且条款禁止改动设计 |
| **Mark / Rice / Wanko** | **0 个** | — | — | ❌ 无表情，只有动作 |

**所以：你要情绪系统生效，就选 Niziiro Mao（也就是项目自带的 `mao_pro`）或 Haru。** 前者已经装好了。

**第 3 步：注册到 `model_dict.json`**

在你的模型作为**新一项**加进这个数组（给上面那项补个逗号）：

```json
{
  "name": "mymodel",
  "description": "我的模型",

  "kScale": 0.3,
  "initialXshift": 0,
  "initialYshift": 0,
  "idleMotionGroupName": "Idle",
  "emotionMap": {
    "neutral": 0,
    "anger": 2,
    "disgust": 2,
    "fear": 1,
    "joy": 3,
    "smirk": 3,
    "sadness": 1,
    "surprise": 3
  },
  "tapMotions": {
    "HitAreaHead": { "": 1 },
    "HitAreaBody": { "": 1 }
  }
}
```

**从 mao_pro 的真实配置能学到 5 件官方文档没写清的事：**

1. **`url` 必须以 `/` 开头**：`/live2d-models/...`，**不能**写成 `./live2d-models/...`。
2. **`url` 要指向 `.model3.json` 的真实位置** —— 注意 mao_pro 多套了一层 `runtime/`。你的模型有没有这一层，按实际目录来。
3. **`idleMotionGroupName` 有大小写讲究**：mao_pro 用的是**大写 `Idle`**，而官方文档示例里写的是**小写 `idle`**。必须和你模型 `model3.json` 里 `Motions` 的组名**完全一致**。填错不会崩，只是模型站着不动。（Live2D 官方这几个示例模型**全都是大写 `Idle`**。）
4. **还有个可选的 `kXOffset`**（mao_pro 是 `1150`）：用来水平微调，文档里没提。模型偏离画面中央时才需要。
5. **`tapMotions` 的外层键是「点击区域名」，不是 `head`/`body`**！Cubism 3/4/5 用的是 `HitAreaHead` / `HitAreaBody` 这种 Id（在 `model3.json` 的 `HitAreas` 里能看到）。官方文档示例里的 `"head"`/`"body"` 是旧写法/简化写法，照抄会**静默失效**。
   - 注意 mao_pro 内层用的是**空字符串 `""`** 作键，因为它的非待机动作就放在一个名字为空的组里。**Haru 则必须写 `HitArea` / `HitArea2`**，照抄 mao_pro 会失效。**以你模型的 `HitAreas` 为准。**

**`emotionMap` 的值要和模型真实的表情对上**。两种写法二选一：

- 写字符串 → 填 `model3.json` 里 `Expressions` 数组的 `"Name"`（如 `"exp_01"`）
- 写数字 → 填数组下标，从 0 开始（推荐新手用这个）

以自带的 mao_pro 为例，它的 `mao_pro.model3.json` 里真实内容是：

```json
"Expressions": [
  {"Name": "exp_01", "File": "expressions/exp_01.exp3.json"},
  {"Name": "exp_02", "File": "expressions/exp_02.exp3.json"},
  {"Name": "exp_03", "File": "expressions/exp_03.exp3.json"},
  {"Name": "exp_04", "File": "expressions/exp_04.exp3.json"},
  {"Name": "exp_05", "File": "expressions/exp_05.exp3.json"},
  {"Name": "exp_06", "File": "expressions/exp_06.exp3.json"},
  {"Name": "exp_07", "File": "expressions/exp_07.exp3.json"},
  {"Name": "exp_08", "File": "expressions/exp_08.exp3.json"}
],
"Motions": {
  "Idle": [{"File": "motions/mtn_01.motion3.json"}],
  "": [{"File": "motions/mtn_02.motion3.json"}, ...]
}
```

所以 `emotionMap` 的值只能在 0~7 之间（它有 8 个表情）。**如果模型只有 2 个表情，就都往这 2 个上映射**（多个情绪映射到同一个表情是允许的 —— mao_pro 自己就这么干：`anger` 和 `disgust` 都是 2、`fear` 和 `sadness` 都是 1）。

`emotionMap` 的**键必须正好是这 8 个英文词**，别自己发明：`neutral` / `anger` / `disgust` / `fear` / `joy` / `smirk` / `sadness` / `surprise`。

> **关于 `defaultEmotion`**：官方文档说它是可选的、用来设默认表情（还能用来遮水印）。但它**没有出现在项目自带的 `model_dict.json` 里**，是否被配置校验接受我没验证过。**建议先别写**；确实需要时再单独试，一旦启动报配置错误就把它删掉。

**别忘了删注释**：JSON 不支持 `//` 注释，写进去会导致整个文件解析失败。

#### 4.2 情绪系统到底怎么工作的（这是你那份说明里最大的误解）

真实机制是这样的：

1. 你启用 `live2d_expression_prompt`（`conf.yaml` 的 `system_config.tool_prompts` 里，**模板默认已启用**）。
2. 系统读取该模型的 `emotionMap` **键**，自动拼成一句提示词注入给 LLM —— 也就是说，**"有哪些情绪、叫什么名字"是模型决定的，不是你写的**。
3. LLM 在回复里输出 `[anger]` 这样的标签。
4. 系统解析标签 → 驱动 Live2D 表情；同时 `tts_preprocessor_config.ignore_brackets: True`（默认值）保证**标签不会被念出来**。

所以：

- ❌ **不要在 `persona_prompt` 里硬列情绪关键词清单**（比如"当你处于 [joy] 时…"）。如果模型没有 `joy` 这个映射，模型就会输出一个系统不认识的表情名，结果就是**表情不变化**。这正是你那份配置的做法，会踩坑。
- ✅ **要做的**：在 `persona_prompt` 里描述**每种情绪下你的语气态度**，但用"积极类 / 愤怒类 / 悲伤类 / 惊讶类"这种不绑定具体单词的说法（我的模板就是这么写的）。这样换任何 Live2D 模型都成立。

**验证表情有没有生效**：启动后故意激怒她或逗她开心，看表情是否变化。不变的话，回到 3.2 第 3 步检查 `emotionMap` 的值是不是真的对应到模型的表情。

#### 4.3 主动说话

`conf.yaml` 的 `system_config.tool_prompts` 里有这一行，**模板默认已启用**：

```yaml
    proactive_speak_prompt: 'proactive_speak_prompt'
```

这就是"AI 主动开口"用的提示词，配合前端触发使用。人设里只需要按模板那样写一段"被要求主动说话时该怎么做"就够了，**不需要额外配置**。

#### 4.4 人设你之后自己改

只改 `persona_prompt` 那一段就行（模板里已经用注释标出范围）。三点注意：

1. **用 `|` 块标量**（模板已是），换行会被保留。
2. **不要用 Tab 缩进**，YAML 只认空格。
3. 段落里**别写中文全角冒号+空格**这种容易踩的格式坑，保持和模板一样的缩进层级（`persona_prompt` 下内容缩进 4 个空格）。

### 第 5 步：MCP 工具（文件搜索 + 屏幕点击）

> **这一整步都是可选的。** 建议先让前面全部跑通、稳定玩两天，再回来加工具。MCP 是"锦上添花"，也是最容易出问题的一环。

#### 5.1 先理解一个前提

**MCP 依赖模型的 Function Calling（工具调用）能力。** Qwen 系列原生支持，所以不用额外配置。但要注意：

- 如果模型不支持工具调用，就得靠 `mcp_prompt` 提示词硬凑（`conf.yaml` 里默认启用），效果差很多。
- **模型越小、量化越狠，工具调用越容易出错**（比如把参数写错、反复调用同一个工具）。

#### 5.2 装 `mcp_servers.json`

把 [mcp_servers.json](C:\work\olv-config\mcp_servers.json) 复制到 `C:\work\Open-LLM-VTuber\mcp_servers.json`。

这个文件里 **`mcp_servers` 是外层键，不能漏**（漏了就静默失效）。我把 `time` 和 `ddg-search` 也留下了 —— 这两个是**项目内置**的，官方默认就预配好，`uvx` 会自动拉取，**零安装**，让 AI 能知道当前时间和上网查东西。

#### 5.3 装"屏幕点击"能力（`windows-mcp`）

这就是你那份说明里的 `win32-mcp-server`，**项目真实存在**，在 [PyPI](https://pypi.org/project/win32-mcp-server/) 上，当前版本 **2.5.1**，提供 **53 个工具**：鼠标点击/拖拽、键盘输入、截图、窗口管理、进程管理、UI Automation、以及结构化 OCR。

- ✅ 不想玩了就在 `mcp_servers.json` 里把 `windows-mcp` 整段删掉，或从角色 YAML 的 `mcp_enabled_servers` 里去掉。

#### 5.4 装"文件搜索"能力（`filesystem`）

**这里我换掉了你原方案里的 `mcp-assist`**，理由：

- `mcp-assist` 的官方 README **只给了 `go build` 编译方式，不提供预编译 exe** —— 对"不写代码"来说等于没有。
- 更重要的：它提供 `execute_command`（**执行任意终端命令**）和 `delete_file`。给一个陪伴型 AI 装这个，风险收益比很差。

改用 **Anthropic 官方的 filesystem server**，只读/写你明确允许的目录，不提供任意命令执行：

```json
"filesystem": {
  "command": "npx",
  "args": [
    "-y",
    "@modelcontextprotocol/server-filesystem",
    "C:\\Users\\36322\\Desktop",
    "C:\\Users\\36322\\Documents",
    "C:\\Users\\36322\\Downloads"
  ]
}
```

**只列你想让它看的目录**，不要写成 `C:\` 或 `C:\Users\36322`（那等于全盘开放）。需要 Node.js（从 <https://nodejs.org/> 装 LTS 版即可，装完重启 PowerShell）。第一次运行 `npx` 会自动下载这个包并缓存，所以**第一次启动会慢十几秒**，属于正常。

```yaml
    agent_settings:
      basic_memory_agent:
        use_mcpp: True
        mcp_enabled_servers:
          - 'time'            # 项目内置，零安装，建议留着
          - 'ddg-search'      # 项目内置，联网搜索
          - 'windows-mcp'     # ← 装好 win32-mcp-server 后再取消注释
          - 'filesystem'      # ← 装好 Node.js 后再取消注释
```

**分阶段启用**：先把 `time` / `ddg-search` 跑通（零安装、零风险，能让 AI 知道当前时间和上网查东西），确认 AI 会用工具了，再逐步放开另外两个。

规则很简单：**`mcp_enabled_servers` 里列出的名字，必须和 `mcp_servers.json` 里的键名一字不差**。只在 `mcp_servers.json` 里定义、没在这里列出的服务器，**不会被加载**。

不用再管老的 `servers_prompt.json` / `formatted_tools.json` —— 新版会在启动时实时连接服务器并动态获取工具列表，那些文件已经废弃了。

#### 5.6 怎么确认 MCP 真的挂上了

启动项目时**盯着控制台日志**。连上 MCP 服务器时会有连接和工具注册的日志输出。如果某个服务器启动失败（路径写错、包没装），日志里会有报错 —— 这时候 AI 会"看起来正常但完全不会用工具"。

常见故障：

| 现象 | 原因 | 解决 |
|---|---|---|
| AI 完全不用工具 | 模型不支持 function calling，或 `use_mcpp: False` | 检查角色 YAML 的 `use_mcpp`；换支持工具调用的模型 |
| 报找不到命令 | `command` 路径不是绝对路径 / venv 里没装 | 用绝对路径；用 `.venv\Scripts\python.exe -m pip install` 装 |
| OCR 报 `TesseractNotFoundError` | Tesseract 没装或没进 PATH | 重装并勾选 Add to PATH |
| 截图/点击坐标偏移 | 高 DPI 缩放 | 跑一次 `health_check` 工具，它会报告 DPI 状态 |
| JSON 解析失败 | 反斜杠没转义 | 路径里全部写成 `\\` |

**配置要点**（和你原方案一致，现已核实）：

- 装好后**托盘常驻，默认开机自启**，第一次启动就自动开始监视游戏。
- 不需要维护模型列表。Steam / Epic / GOG / Xbox / EA / Ubisoft / Battle.net 的游戏**自动识别**；其它游戏可以在它运行时用 **Running apps → Add as game**，或用 **Add game...** 手动添加。
- **每个游戏一条规则**：**On** = 自动暂停；**Off** = 不管这个游戏；**Ask** = 保持 AI 运行，但提供一个"一键暂停"提示，并带 **Always pause** / **Never pause** 记住你的选择。默认是 **On**。
- 想临时手动控制：面板和托盘里都有 **Pause AI** / **Resume AI**，还可以设一个在游戏内也能用的全局快捷键。

**两个必须知道的坑**（都来自作者文档）：

1. **游戏期间 LM Studio 的 HTTP 服务会被停掉**，所以这段时间 Open-LLM-VTuber 的请求会**直接失败**（不是卡住，是报错）。这是设计如此，退出游戏恢复后就正常了。
2. **LM Studio 升级后可能需要等 GamePause 更新**：它恢复设置用的是 LM Studio 的内部协议，作者只在 **LM Studio 0.4.25** 上测过。升级 LM Studio 后请去 **Advanced → Diagnostics** 看一眼，如果抓不到完整快照，GamePause 会**拒绝卸载**（宁可不干活也不搞坏你的配置）—— 这算是安全设计。

> **不装任何软件的手动替代法**：你其实可以自己做等价操作 ——
> ```powershell
> lms unload --all     # 玩之前，把模型卸掉释放内存
> ```
> 玩完**什么都不用管**：因为你开了 **JIT 自动加载**，下次 AI 说话时 LM Studio 会自动把模型装回来。代价是要记得手动执行，好处是零依赖、零风险。

### 第 7 步：BIOS 与 AMD 平台设置

1. **显存 carve-out 设到最低**（512 MB 或 1 GB）。Strix Halo 是统一内存架构，动态分配，让大块内存留给模型和游戏去争。
2. 装**最新版 AMD 驱动**（Adrenalin）。LM Studio 在 Windows 上跑 AMD 核显可以走 **Vulkan**（较成熟）或 **ROCm**（较新，AI Max 系列有官方支持）。装完在 LM Studio 里加载模型时看一眼 **Runtime / Backend** 是不是 GPU。
3. **怎么验证模型真的跑在 GPU 上**：加载模型后打开任务管理器 → 性能 → GPU，看**共享 GPU 内存**是否明显上升（模型 17 GB 的话应该涨十几个 GB）。如果显存没动、CPU 却满载，说明在跑 CPU，速度会差一个数量级 —— 回 LM Studio 把 GPU offload 层数拉满。
4. 128 GB 统一内存下，17 GB 的模型 + 游戏同时跑是完全可行的。**但注意不要让模型被加载两份**：如果你既手动预载了模型、又开了 JIT 自动加载，可能出现两份实例。**建议只留 JIT**。

### 附录 A：故障速查

| 报错 / 现象 | 原因 | 解决 |
|---|---|---|
| `Error calling the chat endpoint...` | LM Studio 服务没跑 / 端口不对 / `model:` 名字错 | 先访问 `/v1/models` 确认服务；`model:` 用 `lms ls` 或接口返回的 id 原样粘贴 |
| `Model not found, try pulling it...` | 模型 id 写错（最常见：全角冒号、多余空格、大小写） | 重新复制 id |
| 连不上 `localhost:1234`，但浏览器能开 | **代理软件没绕过本地地址** | 在代理里把 `localhost` / `127.0.0.1` 设为直连，或临时关代理 |
| 前端黑屏 / 模型加载不出 | 模型是 **Cubism 2**；或 `url` 没以 `/` 开头；或文件夹名写成了 `live2d_models` | 换 Cubism 3+ 模型；改 `url`；确认文件夹叫 `live2d-models` |

| 表情始终不变 | `emotionMap` 的值与模型真实表情对不上；或 `live2d_expression_prompt` 被注释掉 | 对着 `model3.json` 的 `Expressions` 改下标；确认 `tool_prompts` 里那行没被注释 |
| 会把思考内容念出来 | 模型 thinking 模式开着 | 在 LM Studio 里关掉 reasoning / thinking |
| 首字响应很慢（好几秒） | 上下文设太大 / 模型全在 CPU 跑 | 上下文降到 8192～16384；确认 GPU offload 生效 |
| 找不到音频文件错误 | **FFmpeg 没装或没进 PATH** | `winget install Gyan.FFmpeg`，重启终端 |
| YAML 报语法错误 | 用了 Tab 缩进 / 中文标点 / 层级错 | 只用空格缩进，对照模板 |
| JSON 报解析错误 | 路径反斜杠没转义成 `\\`；数组项漏逗号 | 修正转义和逗号 |
