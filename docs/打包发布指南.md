# 打包发布指南

> 目标：把这个定制版安全地发布到你的 GitHub 仓库，别人 clone 后跑一条命令就能用。
>
> **核心原则：仓库里只放代码 + 配置模板 + 脚本，不放模型、不放密钥、不放虚拟环境。**

---

## 一、绝对不要提交的东西

| 内容 | 体积 | 为什么不能传 |
|---|---|---|
| `.venv/` | ~1.5 GB | 依赖目录，各机器不同，且巨大 |
| `models/`（TTS/ASR 模型）| ~412 MB | 大二进制，脚本自动下载即可 |
| `live2d-models/` | ~14 MB | **版权问题**，Live2D 协议 4.1.1 禁止再分发 |
| `conf.yaml` | 小 | **含你的 API key** |
| `mcp_servers.json` | 小 | 含你的本机绝对路径（`C:\Users\你的名字\...`）|
| `cache/`、`logs/`、`chat_history/` | 不定 | 运行产物 + 可能含对话隐私 |
| `.env`、`api_keys.py` | 小 | 密钥 |

这些**已经全部写进** [`.gitignore`](../.gitignore) 了。但 `.gitignore` 只能防"不小心 add"，
**防不住 `git add -f`**，也防不住已经进过历史记录的文件。所以发布前必须做下面第 3 步的检查。

## 二、正确的发布流程（推荐用 Fork）

### 为什么强烈建议 Fork

直接 Fork 而不是"下载 zip 再建新仓库"，有三个实际好处：

1. **git 历史保留**，原作者的每次提交都在，版权归属一目了然
2. **GitHub 上显示"forked from"**，不会被误认为你原创
3. **方便跟进上游更新**，以后原作者修了 bug 你可以直接合并

```powershell
# 1) 先在 GitHub 网页上 Fork 原仓库：
#    https://github.com/Open-LLM-VTuber/Open-LLM-VTuber  →  点 Fork

# 2) 克隆你的 fork
git clone https://github.com/<你的用户名>/Open-LLM-VTuber.git
cd Open-LLM-VTuber

# 3) 加上游仓库（方便以后同步）
git remote add upstream https://github.com/Open-LLM-VTuber/Open-LLM-VTuber.git

# 4) 把本定制版的文件覆盖进去
#    - 用本目录的 .gitignore 替换仓库根的 .gitignore
#    - 把 scripts/ 复制过去
#    - 把 extras/ 复制过去
#    - 把 docs/ 复制过去
#    - 用本目录的 README.md 替换（或合并）

# 5) 关键：确认 Live2D 模型没有进 git
git check-ignore -v live2d-models/mao_pro/runtime/mao_pro.model3.json
#    应该输出：.gitignore:xx:/live2d-models/*  live2d-models/...
#    如果没有任何输出，说明它【会被提交】——必须修 .gitignore！
```

### 如果模型已经在 git 历史里了

原仓库**故意跟踪了** `mao_pro` 和 `shizuku`。你 fork 后它们已经在历史提交中，
**光改 `.gitignore` 是没用的**（历史里的文件依然存在，clone 依然会下载）。

要真正移除，需要重写历史：

```powershell
# 方案一：用 git filter-repo（推荐，需先安装）
#   pip install git-filter-repo
git filter-repo --path live2d-models/ --invert-paths

# 方案二：简单粗暴——从一个干净的历史点重新开始
#   这会丢掉历史，但最省事、最不容易出错
Remove-Item .git -Recurse -Force
git init
git add .
git commit -m "Open-LLM-VTuber personal customization"
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

> 权衡：方案一保留历史（推荐，尊重原作者）；方案二丢失历史但保证干净。
> 如果只是想自己用、不在意 history，**方案二最省心**。

## 三、发布前必做：安全检查

我写了个检查脚本，会扫描**将要提交的文件**里有没有密钥、大文件、模型文件：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\check-before-push.ps1
```

它会检查：

- 待提交文件里有没有看起来像 API key 的字符串（`sk-`、`tvly-`、`Bearer` 等）
- 有没有超过 10 MB 的文件
- `live2d-models/`、`models/` 是否被正确忽略
- `conf.yaml`、`mcp_servers.json` 是否被正确忽略

**任何一项 FAIL 都不要 push。**

### 手动兜底检查

```powershell
# 看将要提交什么
git status --short

# 在所有已跟踪文件里搜密钥
git grep -n -i -E "sk-[a-zA-Z0-9]{16,}|tvly-|api[_-]?key['\"]?\s*[:=]\s*['\"][^'\"]{8,}" -- . ':!*.md'

# 找大文件（超过 5 MB 的已跟踪文件）
git ls-files -z | ForEach-Object { $_ -split "`0" } | Where-Object { $_ } | ForEach-Object {
  if (Test-Path $_) { $f = Get-Item $_; if ($f.Length -gt 5MB) { "{0,8:N1} MB  {1}" -f ($f.Length/1MB), $_ } }
}
```

## 四、README 里必须写清楚的东西

一个负责任的二次分发 README 应该包含：

- [x] **明确说明基于哪个项目**，附原仓库链接
- [x] **保留原作者署名**
- [x] **保留 LICENSE 原文**（MIT 的硬性要求）
- [x] 说明哪些文件**不包含**在仓库里（模型），以及为什么（授权）
- [x] 说明使用者需要**自行下载**什么
- [x] 如果改过源码，说明改了哪里

本目录的 [README.md](../README.md) 已经按这个标准写好，可以直接用。

## 五、别人 clone 后的体验

理想流程（一条命令）：

```powershell
git clone <你的仓库>
cd <仓库>
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1
.\scripts\start.bat
```

`setup.ps1` 已经覆盖了：装 uv/ffmpeg → 装依赖 → 下 TTS 模型 → 检查 Live2D 模型 → 生成 conf.yaml。

**唯一需要人工的两步**（无法自动化，且必须由使用者自己做）：

1. **下载 Live2D 模型**——法律上不能替他下，脚本会提示官方地址
2. **装 LM Studio 并加载模型**——GUI 程序，需要人工操作

这两步要在 README 里**写得非常显眼**，否则别人会卡住。

## 七、关于"能不能直接打包 zip 分享"

**可以，但仅限私下分享**，并且要注意：

- 体积会到 **2 GB**（因为含 `.venv`），传输和存放都不划算
- 仍然**不能**把 Live2D 模型放进去——协议禁止的是"再分发"，不管你用 git 还是网盘
- zip 分享给朋友，朋友拿到的是你机器上的绝对路径，很容易出问题

**更推荐的做法**：就算只给朋友用，也走 git clone + setup 脚本这条路。
一个 `git clone` + 一条命令，比传 2 GB 压缩包体验好得多。
