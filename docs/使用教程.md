## 一、第一次使用（10 分钟）

### 第 1 步：确认两个服务在跑

她需要**两个服务**同时运行：

| 服务 | 端口 | 作用 |
|---|---|---|
| LM Studio | 1234 | 跑大模型（对话 + 记忆） |
| Open-LLM-VTuber | 12393 | 交互核心（语音、Live2D、记忆） |

**开机登录 Windows 后它们会自动启动**（看门狗负责，约 1 分钟就绪）。

自己检查一下：

```powershell
Test-NetConnection 127.0.0.1 -Port 1234  -InformationLevel Quiet   # 应返回 True
Test-NetConnection 127.0.0.1 -Port 12393 -InformationLevel Quiet   # 应返回 True
```

两个都是 `True` 就继续。有一个 `False` 看[第十节](#十出问题怎么办)。

### 第 2 步：打开网页

用 **Chrome** 打开：

```
http://localhost:12393
```

> ⚠️ 官方只推荐 Chrome，Edge 有已知问题。

### 第 3 步：选角色（**这步最关键**）

点右上角的**角色选择**，选 **「小星(记忆版)」**。

**为什么必须选这个**：只有它启用了记忆系统。选错了她不会记事，也不会用我配的语音方案。

### 第 4 步：试说话

界面上找**麦克风按钮**：

1. 点一下 → 开始录音（按钮会有变化）
2. 说一句，比如"你好，介绍一下你自己"
3. 再点一下 → 结束录音
4. 等几秒，她会**用语音回你**

**首次回复会慢**（模型要加载，可能 30-60 秒），之后正常 4-6 秒。

### 第 5 步：确认记忆在工作

随便聊两三句，然后打开这个文件：

```
C:\work\Open-LLM-VTuber\memory\short_term.md
```

应该能看到刚才聊的内容被记成了表格：

```markdown
| 编号 | 时间 | 场景 | 事件（客观事实） |
| S001 | 2026-10-15 14:20 第1天 | 日常 | 用户向角色问好并请其自我介绍 |
```

**看到这个就说明整套系统跑通了。**

## 三、跟她说话的技巧

### 她能"听懂"的语音特点

- **中文优先**，中英混说也可以（TTS 模型是中英双语）
- 语速正常即可，不用刻意放慢
- 环境噪音大时识别率会下降

### 说话里带日期，她会去翻记忆

这是记忆系统最有用的功能。你说这些词时，**她会自动调取对应那天的记录**：

| 你说 | 她会调取 |
|---|---|
| "昨天我们聊了什么" | 昨天的全部记录 |
| "上周三说到哪了" | 上周三的 |
| "10月14日那天" | 10 月 14 日的 |
| "第3天" | 第 3 天的 |
| "3天前" | 3 天前那天 |

### 她会主动记住什么

对话结束后，一个**小模型**会读这轮对话，抽出一条"客观事实"。比如：

| 你说 | 她记的 |
|---|---|
| "我今天开了一整天的会" | 用户参加了一整天的会议 |
| "下周我要搬去杭州" | 用户计划下周搬去杭州 |
| "算了先睡了晚安" | 用户向角色告别并准备休息 |

**注意**：她记的是**客观事实**，不是你的原话，也不记她的主观感受。

### 什么不会被记住

- 纯寒暄（"哈哈"、"嗯嗯"）—— 抽不出有效事实就不会记
- 抽取失败的那轮（不影响对话，只是没记上）

## 四、记忆系统怎么用

### 两层结构

```
短期记忆 (short_term.md)  ← 每轮对话记一条
        ↓  满 7 条自动"固化"
长期记忆 (long_term.md)   ← 按主题归并成 1~3 条
```

同时**每条都会按日期归档**到 `archive/`，这就是"提日期能回忆"的基础。

### 文件在哪、长什么样

```
C:\work\Open-LLM-VTuber\memory\
├── long_term.md          长期记忆
├── short_term.md         短期记忆（当前积累中）
├── day_counter.json      "第 n 天"计数
├── memory.log            写入日志
└── archive\
    ├── INDEX.md          日期索引 ← 想看"哪天聊了什么"看这个
    ├── index.json        机器可读的索引
    └── 2026-10-15.md     当天全部记录
```

**长期记忆实际内容**（格式：编号 | 时间 | 场景 | 事件）：

```markdown
| 编号 | 时间 | 场景 | 事件（客观事实） |
| L001 | 2026-10-14 20:07 第1天 → 20:07 第1天 | 工作 | 用户参加了一整天的会议，项目次日上线。 |
| L002 | 2026-10-14 20:07 第1天 → 20:07 第1天 | 日常 → 工作 | 用户决定下周搬去杭州，母亲将帮忙收拾东西。 |
```

**时间**是起止双时间戳（跨天事件能正确表达），**场景**是 `起点 → 终点`。

### 固化什么时候触发

**短期记忆满 7 条时**，下一轮对话会触发固化：

- 7 条归并成 1~3 条长期记忆（按**主题**归并，不是死板合成一条）
- 然后清空短期记忆
- 固化在**后台进行**，耗时 3-8 秒，不阻塞对话

### 三种用法

**① 想知道她记了什么** → 直接打开 `long_term.md`（就是 Markdown 表格）

**② 记错了想改** → 直接编辑文件。程序**只做追加，不会覆盖你的修改**。

**③ 想清空重来** → 删掉这三个的内容，程序会自动重建：

```
memory\long_term.md
memory\short_term.md
memory\archive\ 里除 INDEX.md 外的文件
```

### 想看某天的历史记录

打开 `memory\archive\INDEX.md`：

```markdown
| 日期 | 星期 | 第n天 | 条数 | 摘要 |
| 2026-10-14 | 周三 | 第1天 | 7 | 用户向角色告别并表达明天加油的鼓励 |
| 2026-10-15 | 周四 | 第2天 | 3 | 用户询问了记忆系统的工作原理 |
```

想看详情就打开对应日期的文件，比如 `archive\2026-10-14.md`。

### 改"第 n 天"的起点

编辑 `memory\day_counter.json` 里的 `start_date`。

| `characters\zh_米粒.yaml` | 米粒 | 项目自带示例 |
| `characters\zh_翻译腔.yaml` | 翻译腔-神经大人 | 项目自带示例 |

在**右上角角色选择**里点一下就切，不用重启。

### 改人设（最常做的事）

只改一个地方：

```
C:\work\Open-LLM-VTuber\characters\xiaoxing_mem.yaml
```

找到 `persona_prompt: |` 开头的段落，改成你想要的性格，保存，**刷新网页**。

**三条纪律**：

**① 别在 `persona_prompt` 里列情绪关键词**（如"当你处于 [joy] 时…"）
情绪词是系统根据 Live2D 模型自动注入的，自己列反而会和实际表情对不上。
描述语气就行，例如"积极类情绪：语气活泼多用感叹号"。

**② 只用空格缩进，别用 Tab** —— YAML 对 Tab 会报错。

**③ 段落缩进要和模板一致**（`persona_prompt` 下内容缩进 4 个空格）。

### 加一个全新角色

1. 复制 `characters\xiaoxing_mem.yaml` → `characters\你的角色.yaml`
2. 改这几个字段：

| 字段 | 说明 |
|---|---|
| `conf_name` | 显示名（随便起） |
| `conf_uid` | **必须唯一**，如 `my_char_001` |
| `character_name` | 她会自称的名字 |
| `human_name` | 她称呼你什么 |
| `persona_prompt` | 人设正文 |

3. 保存 → 刷新网页 → 角色选择里就有

> **记忆是共享的**：所有角色读同一个 `memory/` 目录。
> 想让某角色用独立记忆，在它的 `memory.dir` 里写不同路径。

## 七、换模型 / 调速度

### 当前配置

| 用途 | 模型 | 大小 |
|---|---|---|
| **角色对话** | `qwen3.6-35b-a3b k-m`（MoE） | 21.2 GB |
| **记忆抽取/固化** | `qwen2.5-3b-instruct` | 2.1 GB |

### 看已装了哪些模型

```powershell
& "$env:USERPROFILE\.lmstudio\bin\lms.exe" ls
```

### 改模型

改**两个地方**（都要改，否则不一致）：

```
conf.yaml                              → 第 141 行附近
characters\xiaoxing_mem.yaml           → llm_configs 段
```

把 `model:` 的值改成目标模型。**必须和接口返回的 id 完全一致**：

```powershell
(Invoke-RestMethod http://127.0.0.1:1234/v1/models).data.id
```

### ⚠️ 铁律：`max_tokens` 不能删

`conf.yaml` 里主模型的 `max_tokens: 1024` **必须保留**。

**原因**：推理模型回复前会先生成"思考"内容。不设上限时，LM Studio 的默认预算会被思考全吃掉，**正文为空**——表现就是**角色完全不出声**，而日志里只看到一句无害的 `Ignore OOV`，极难排查。

实测：

| `max_tokens` | 思考 token | 正文 |
|---|---|---|
| 60 | 60 | **空** |
| 400 | 109 | 105 字 ✅ |
| 1024 | ~100 | 正常 ✅ |

### 换模型时避免抢显存

**别让两个大模型同时驻留**——实测 MoE 独占时首字 5.4s，和大模型共存时退化到 12-21s。

```powershell
$lms = "$env:USERPROFILE\.lmstudio\bin\lms.exe"
& $lms unload "不需要的模型"
& $lms load "要用的模型" --gpu 1.0 -y    # --gpu 1.0 才真正全卸载到 GPU
```

> ⚠️ `--gpu max` 实测不如 `--gpu 1.0` 彻底。

### 想让对话更快

降上下文。模型默认配置在：

```
C:\Users\36322\.lmstudio\.internal\user-concrete-model-default-config\
```

把 `contextLength` 从 `262144` 改成 `16384`，实测能快 **6 倍**（流式首字 31.7s → 5.0s）。

### 模型实测速度（同口径：独占 GPU）

| 模型 | 热态首字 |
|---|---|
| qwen3.8-27b-uncensored（27B 稠密） | **3.0s** |
| qwen3.6-35b-a3b k-m（35B-A3B MoE） | 6.4s |

想换回 27B：包内有备份 `config-backup-27B\`，或直接改 `model:` 值。

## 八、联网搜索与工具

### 现在能用什么

| 工具 | 作用 | 试试说 |
|---|---|---|
| `time` | 让她知道现在几点 | "现在几点了" |
| `ddg-search` | DuckDuckGo 联网搜索 | "帮我搜一下今天有什么 AI 新闻" |

两个都**零安装**（已用 `uv tool install` 装好）。

### 加新工具

编辑 `C:\work\Open-LLM-VTuber\mcp_servers.json`：

```json
"你的工具名": {
  "command": "C:\\完整\\绝对\\路径\\工具.exe",
  "args": ["参数"]
}
```

然后在角色 YAML 的 `mcp_enabled_servers` 里加上 `'你的工具名'`，**重启服务**。

**两条硬规则**：

**① `command` 必须写绝对路径**
源码只在命令**字面等于** `npx`/`uvx`/`node` 时检查 PATH，其他情况**完全不验证文件是否存在**——路径写错会**静默失败**。

**② 注册了还要在角色里启用**
`mcp_servers.json` 定义不够，必须在角色的 `mcp_enabled_servers` 里列出名字。

参考脱敏模板：`mcp_servers.example.json`

### 接入自定义 HTTP 接口

用附带的通用桥接，**改 JSON 就能接入任意 HTTP API，不用写代码**：

1. 参考 `extras\http_tools.example.json` 建 `extras\http_tools.json`
2. 在 `mcp_servers.json` 注册（参考 example 里的 `http-bridge` 段）
3. 角色 YAML 启用 → 重启

详见 `docs\网络API方案.md`。

## 十、出问题怎么办

### 通用排查顺序

```powershell
# 1) 端口通不通
Test-NetConnection 127.0.0.1 -Port 1234  -InformationLevel Quiet
Test-NetConnection 127.0.0.1 -Port 12393 -InformationLevel Quiet

# 2) 模型加载了吗
& "$env:USERPROFILE\.lmstudio\bin\lms.exe" ps

# 3) 模型 id 对不对
```

### 常见问题速查

| 现象 | 原因 | 解决 |
|---|---|---|
| **角色完全不出声** | ① 推理模型吃光 token 预算 ② `tts_model` 不对 | ① 确认 `conf.yaml` 有 `max_tokens: 1024` ② 确认 `tts_model: 'sherpa_onnx_tts'` |
| **会打字但没声音** | TTS 环节失败 | 看日志有没有 `edge_tts ... 403` |
| **连不上 1234** | 代理没绕过本地地址 | 代理设置里把 `localhost`/`127.0.0.1` 设为直连 |
| **`Model not found`** | model 值写错 | 从 `/v1/models` 原样复制（注意大小写、空格） |
| **记忆写不进去** | LM Studio 那个设置被改了 | 确认 `~\.lmstudio\settings.json` 里 `unloadPreviousJITModelOnLoad: false`，**改完要重启 LM Studio** |
| **记忆错位一轮** | 已修的历史 bug | 若复现，看 `memory\diag.log` |
| **首次回复很慢（30-60s）** | 模型正在加载 | 正常，之后就快了 |
| **启动卡在 `Initializing TTS`** | 正在加载 162MB TTS 模型 | 等 1-2 分钟，正常 |
| **提示"Windows 已保护你的电脑"** | 桌面版未签名 | 更多信息 → 仍要运行 |
| **YAML 报语法错误** | Tab 缩进 | 只用空格 |
| **找不到音频文件** | FFmpeg 不在 PATH | 用 `scripts\start.bat` 启动（它会补 PATH） |
| **服务莫名停止** | 可能拔了电源 | 插上电源；或看 `watchdog.log` |
