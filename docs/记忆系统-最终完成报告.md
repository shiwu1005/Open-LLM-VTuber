## 二、本次新增：专用记忆模型

### 配置（`characters/xiaoxing_mem.yaml`）

```yaml
        memory:
          enabled: true
          dir: 'C:/work/Open-LLM-VTuber/memory'   # 绝对路径，避免跟着 cwd 跑偏
          stm_fix_threshold: 7
          # ↓ 关键：把抽取/固化交给一个小的非推理模型
          memory_llm_provider: 'memory_llm'
          internal_max_tokens: 1024
          consolidation_max_tokens: 2048
          internal_timeout: 60
          consolidation_timeout: 180

    llm_configs:
      lmstudio_llm:              # 角色主模型（对话用）
        model: 'qwen3.8-27b-uncensored'
        ...

      memory_llm:                # 记忆专用小模型
        base_url: 'http://localhost:1234/v1'
        llm_api_key: 'lm-studio'
        model: 'qwen2.5-3b-instruct'
        temperature: 0.2         # 结构化任务要稳定
        max_tokens: 1024
```

留空 `memory_llm_provider` 则回退到主模型（原行为不变）。

已下载的模型：`Qwen/Qwen2.5-3B-Instruct-GGUF` 的 `q4_k_m`（2.10 GB，**非推理**，所以没有 97 秒思考）。

## 三、这次修掉的 6 个 bug（全是实测才暴露）

### bug 1：LM Studio 不允许两个模型同时驻留（**最关键**）

```
Failed to load model "qwen2.5-3b-instruct".
Error: Engine protocol startup was aborted.
```

原因是我在 `~/.lmstudio/settings.json` 里发现的一个设置：

```json
"unloadPreviousJITModelOnLoad": true    ← 加载新模型时卸载旧模型
```

角色对话用 27B、记忆用 3B，两者来回抢占：一个加载就踢掉另一个。而主模型的 MCP 工具调用会在同一轮再发起一次请求，于是互相打断，**记忆全部写不进去**。

**修法**：改成 `false`。你有 128 GB，两个模型共 19.6 GB 完全放得下。改完实测两者同时驻留：

```
qwen2.5-3b-instruct       2.10 GB
qwen3.8-27b-uncensored   17.48 GB
```

> ⚠️ 这个设置改的是 LM Studio 全局配置，改完**需要重启 LM Studio** 才生效。

### bug 2：`memory_llm` 没有注册到 provider 工厂

```
ERROR | Failed to create memory LLM 'memory_llm': Unsupported LLM provider
        Falling back to the main LLM.
```

`stateless_llm_factory.py` 是按硬编码的 provider 名单分发的，我加了配置字段但没加这个分支。
**修法**：把 `memory_llm` 加入该名单（复用 OpenAI 兼容客户端）。

### bug 3：一行 import 被合并，整个模块语法错误

```
SyntaxError: invalid syntax
from pathlib import Pathfrom typing import Any, AsyncIterator, ...
```

我早前一次编辑删掉了一个换行符，把两行 import 粘在一起。**这个错误会让记忆 agent 完全无法加载**，
而日志里只表现为"配置切换成功但什么都不发生"，很隐蔽。

### bug 4：模型调用的容错缺失

小模型加载失败时，记忆是**静默丢弃**的。已加三级兜底：
1. 用专用小模型
2. 失败 → 等 2 秒重试一次（应对瞬时加载竞争）
3. 仍失败 → 回退用主模型（它一定已加载）

### bug 5：小模型会自己造场景词

3B 模型输出 `日常工作` 这种不在允许列表里的词，导致场景转换判断失效（每一行都像转换）。
**修法**：加 `normalize_scene()` 在 `add_ltm()` 内部强制归一化（确定性，不额外调 LLM），12 项单测全过：

```
日常工作 → 工作    游戏娱乐 → 游戏    工作相关 → 工作
闲聊 → 日常        日常生活 → 日常    深夜 → 日常（不再误判成"深夜闲聊"）
```

### bug 6：固化超时太短

实测固化要 96.8 秒，而超时设的 90 秒。已拆成独立参数 `consolidation_timeout`（默认 300 秒，你配置里是 180）。

## 六、使用方式

前端角色选择里选 **「小星(记忆版)」**。之后：

- 正常聊天 → 每轮**自动记一条 STM 并归档到当天**
- 攒满 7 条 → **下一轮自动固化**成 LTM，STM 清空
- 说话带日期（`昨天`/`上周三`/`10月14日`/`第3天`）→ **自动调取那天的归档**
- 想看记忆：直接打开上面那几个 `.md` 文件

**延迟**：抽取 1-2 秒、固化 3-8 秒，**都在语音播完之后后台进行**，不阻塞对话。

## 七、注意事项

1. **LM Studio 的 `unloadPreviousJITModelOnLoad` 必须保持 `false`**，否则两个模型会互相踢，
   记忆写入会全部失败。改完要**重启 LM Studio**。
2. 若换用别的小模型，把 `llm_configs.memory_llm.model` 改成 `/v1/models` 里的准确 id。
3. 记忆系统用的是**主模型之外**的第二个模型，所以 LM Studio 里会同时驻留两个（共约 19.6 GB）。
   内存紧张时可把小模型上下文设小些。
4. `basic_memory_agent` 与原 `conf.yaml` **未被改动**，随时可切回。
