# 记忆库目录说明

> ⚠️ **这个目录里的文件是你的私人数据，不要上传到公开仓库。**
>
> `.gitignore` 已排除 `memory/*`（只保留本说明文件）。
> 如果你把 `long_term.md`、`short_term.md`、`archive/` 提交上去了，
> 等于把你的作息、工作安排、家庭情况、搬家计划等真实生活记录公开出去。

---

## 目录结构

```
memory/
├── README.md              本说明（唯一会被提交的文件）
├── long_term.md           长期记忆：编号 | 时间(起→止) | 场景(起→止) | 事件
├── short_term.md          短期记忆：编号 | 时间 | 场景 | 事件
├── day_counter.json       "第 n 天" 计数与起始日期
├── memory.log             写入/固化的操作日志
├── diag.log               排错用诊断日志
└── archive/
    ├── INDEX.md           日期索引（人可读）
    ├── index.json         日期索引（机器可读）
    └── YYYY-MM-DD.md      每天一个归档，当天发生的所有事情
```

## 它是怎么工作的

1. **每轮对话**结束后，记忆系统用一个小模型读这轮对话，抽出一条"客观事实"，
   写进 `short_term.md`，同时归档到 `archive/今天.md`
2. **短期记忆满 7 条**时，下一轮触发**固化**：把 7 条归并成 1~3 条写进
   `long_term.md`（按主题合并，不是死板合成一条），然后清空 `short_term.md`
3. **每轮对话前**，两张表 + 归档索引会被注入到角色的 system prompt 里，
   所以角色"记得"这些事
4. **你说话里带日期**（`昨天` / `上周三` / `10月14日` / `第3天`）时，
   会**自动调取那天的归档**内容一起注入

## 所有文件都是人可读的

就是 Markdown 表格，**可以直接手工编辑修正**。程序每次是追加写，不会覆盖你的修改。

例：
```markdown
| 编号 | 时间 | 场景 | 事件（客观事实） |
| L001 | 2026-10-14 20:07 第1天 → 2026-10-14 23:00 第1天 | 工作 | 用户参加了一整天的会议，项目次日上线。 |
```

## 想清空重来

删掉 `long_term.md`、`short_term.md`、`archive/` 里的内容即可（程序会自动重建）。
`day_counter.json` 决定"第 n 天"从哪天算起，改里面的 `start_date` 就能换起点。

## 想换记忆模型

记忆的抽取和固化是结构化任务，不需要大模型。在角色 YAML 里指向一个小模型会快很多：

```yaml
        memory:
          memory_llm_provider: 'memory_llm'   # llm_configs 里的键名
```

实测对比（同一份 7 条数据做固化）：

| 模型 | 耗时 |
|---|---|
| 27B 推理模型 | 96.8 秒 |
| **3B 非推理模型** | **3-8 秒** |

详细配置见项目根目录的 `docs/` 文档。
